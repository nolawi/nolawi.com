Why a shared kit?

When every screen starts from scratch, teams make the same layout and styling decisions over and over. A shared foundation gives people a place to start and makes the patterns easier to find later.

What’s in the repository

The Delano README describes an application foundation with a layout module, shared styles, and a style-guide entry point. The project uses Angular and Less, with Nebular listed among its dependencies. There’s also a documentation command that uses Compodoc.

What I’d take forward

I’d document the behavior alongside the visuals. For a component like a dialog, that means writing down what receives focus on open, how to close it, and where focus returns. The portfolio playground shows that idea in a small, separate example.
